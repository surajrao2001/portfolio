# Voice guide

Short style guide for site copy. Not a full copy deck — enough so new pages stay on-tone.

## One-line rule

Specific and self-aware beats generic and try-hard.

## Tone

- Casual, clear, slightly dry humor — never stand-up forced.
- Confidence without resume buzzwords.
- Prefer concrete work and trade-offs over personality branding fluff.
- Visitor is smart; don't over-explain or under-sell.

## Agreed lines (use or paraphrase, don't mutate the tone)

| Surface | Line |
| --- | --- |
| Hero headline | Building products worth looking under the hood of. |
| Hero support | Projects with real systems underneath, writing when something was worth explaining, and a contact form that actually emails a person. |
| About (home teaser) | I care more about the boring middle of a feature than the demo GIF. The middle is where judgment shows up. |
| Project card | What I built, why the trade-offs, what I'd do differently next time — not a feature dump. |
| Skills | Tools I actually reach for — not a keyword dump for ATS robots. |
| Home CTA | Let's build something that holds up past the demo. |
| Contact | Say what you're trying to do. Skip the "hope this finds you well." |

## Do

- Name the actual constraint ("one API route on purpose").
- Let humor come from specificity ("Git is the CMS").
- Keep sentences short enough to scan.

## Don't

- Generic startup jokes ("I turn coffee into code", "ninja", "rockstar").
- Corporate mush ("synergistic full-stack solutions", "passionate about leveraging").
- Fake humility that still brags ("just a humble 10x engineer").
- Emoji ribbons, exclamation spam, or motivational poster copy.

## When writing new UI copy

1. Would this still make sense if the visitor was tired and in a hurry?
2. Could another portfolio drop the same sentence unchanged? If yes, rewrite.
3. Check it against the one-line rule above.
